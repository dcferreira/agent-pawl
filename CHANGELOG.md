## v0.3.0 - 2026-09-25

### Breaking

* **`pawl run` now refuses to start without the enforcement hooks** (exit 4). It needs a
  `PreToolUse` heartbeat for the working copy from the last 5 minutes. The Claude Code plugin
  wires the hooks for you; for a non-plugin install, see the `settings.json` snippet in
  `docs/install.md`. To opt out, pass `--no-enforcement` or set `PAWL_ENFORCEMENT=off`. Resuming a
  run keeps the mode it started with (#14).

### Added

* **Enforcement hooks** (`pawl hook pre|stop`, #14):
  * `Stop` won't let the driving session end its turn while a run is waiting on a `pawl submit`
    for an `agentic`/`parallel` step.
  * `PreToolUse` enforces `guards:` and stops subagents from mutating git/jj while a run is live.
* **`guards:`** is validated and no longer rejected (#12). Guards are enforced by the
  `PreToolUse` hook. They are advisory regex matches, not a semantic guarantee.
* **`retry:`** on `deterministic` and `wait` steps (#13) re-runs a hard-failed body before any
  outcome is resolved. That covers a non-zero exit, a timeout, or stdout pawl can't parse. It is
  separate from `attempts:`. See format-spec §B.16.
* **`invariants:`** are checked by the engine after every step and every `pawl
  submit`/`pawl poll` (#16). A violation blocks the run with the invariant's `message:`. For a
  `parallel` step, they are checked once, when the group joins.
* **`pawl update [--check] [--version vX.Y.Z] [--force]`** updates the binary in place from a
  GitHub release (#10). It verifies the checksum before writing anything, and it refuses to
  replace a source (`dev`) build unless you pass `--force`.
* The **`review-pr` workflow now converges** (#15). It uses only Claude reviewers, re-reviews only
  the delta after round 1, keeps a findings ledger, uses a scoped fixer, and stops after 4 rounds.
* Docs fixes (#11, #17). The plugin manifest version now tracks the release (0.3.0).

### Known limitations

* The enforcement hooks key on the Claude Code session's start directory. A session that drives a
  run in a different working copy, such as `cd <jj-workspace or git worktree> && pawl run …`,
  never passes the heartbeat gate, and the hooks don't see that run. Start the session in the
  working copy you run in, or pass `--no-enforcement`. Tracked in #18.

## v0.2.0 - 2026-09-23

### Breaking

* **Exit codes now follow the documented table** (`docs/cli.md`):
  * `pawl run`/`submit`/`poll` exit **3** when the run ends BLOCKED. Before, they exited 0.
  * Refusals exit **4**: lock held, workflow file changed, a step or kind that isn't current, or a
    run that has already finished.
  * Engine errors, such as a broken run directory, exit **5**.
  * Validation and YAML parse failures exit **2**. Before, they exited 1.
  * `pawl status` still exits 0 whenever the lookup works. `pawl poll` still exits 0 when the run
    has moved on.
* **`pawl validate --strict` is now an error** (exit 2). It never existed, and before it was read
  as a workflow name. `validate` takes `<workflow-name>` or the new `--path <file>`.
* **New validator rule 18** rejects `context:` entries that start with `!` but lack the YAML
  `!cmd` tag, such as `"!git diff"` or an unquoted `!git diff`. Those entries used to be read as
  file paths. Write `!cmd "git diff"` instead.

### Added

* `pawl abandon --reason <text>`, `pawl status --json`, and `pawl validate --path <file>`.
* The `review-pr` workflow.

### Changed

* `examples/` moved to `docs/examples/`.

## v0.1.0 - 2026-09-22

Initial release. `agent-pawl` (binary `pawl`) is a state-machine workflow engine for Claude Code:
a workflow is one YAML file, sequencing lives only in `next:`/`outcomes:`/`catch:`, and the engine
owns the run cursor and evaluates every postcondition itself.

### Added

* The core engine: `${key}` substitution (`internal/render`), YAML types/loader/validator
  (`internal/spec`), the stdout grammar `deterministic`/`wait` steps use to report outcomes
  (`internal/emit`), the run journal (run directory, event log, pure replay, lock)
  (`internal/journal`), and the run cursor (`internal/engine`).
* The `pawl` CLI and the `/wf` handshake output.
* Three step kinds: `deterministic`, `agentic`, and `parallel`; `wait` and `human` followed shortly
  after.
* `docs/examples/green-tests`, the first verified-runnable example, covered end-to-end by `e2e/`.
* Installation as a Claude Code plugin, alongside `go install`.
* `install.sh` and goreleaser-based release binaries, published via tagged GitHub Releases.
* CI: gofmt, vet, the test suite (including the race detector and staticcheck), `go mod tidy`
  drift checks, and jj-workspace coverage alongside the assumed git path.
* An MIT licence and `AGENTS.md` orientation for AI agents working in the repo.

### Fixed

* Run-directory slug collisions and script paths, closing a path-handling bug found while
  building the run journal.
* Working-copy root resolution no longer shells out to a VCS binary at runtime.

### Changed

* The project was renamed from `wf` to `agent-pawl`, and the binary from `wf` to `pawl`.
