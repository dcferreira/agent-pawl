## v0.9.0 - 2026-10-15

### Added

* `docs/examples/README.md` lists which examples are proven in e2e and which are authoring exercises, and a test keeps that true. `wait-for-build`, `human-approval` and `parallel-fanout` now run end to end in `e2e/` (agentic answers canned); `brain-dispatch`, `manage-mr` and `dependency-upgrade` are labelled "Authoring exercise, not run"; `manage-mr` and `dependency-upgrade` ship placeholder scripts for everything they reference, and `brain-dispatch`'s `NOTES.md` lists its unshipped external dependencies. `human-approval/notes.md` is now `NOTES.md`. ([#67](https://github.com/dcferreira/agent-pawl/pull/67))
* `pawl --version` and `pawl -v` print the version, the same as `pawl version`. ([#82](https://github.com/dcferreira/agent-pawl/pull/82))

### Changed

* `pawl run`'s version-mismatch refusal now names the stale binary's path and the exact command to fix it, and the /pawl skill stops and reports it instead of trying to fix the install itself. ([#73](https://github.com/dcferreira/agent-pawl/pull/73))
* The `/pawl` skill now says to pass `subagent_args` to the subagent and to state a field the harness can't enforce (such as `tools`) in the subagent's prompt; the docs explain `blocked` as how a workflow gives up, what `${visits}` means in a terminal message, and how to test failure paths. ([#83](https://github.com/dcferreira/agent-pawl/pull/83))

### Fixed

* The docs' sample output is now captured from real runs (and a test keeps it current); earlier examples showed output pawl never printed. ([#70](https://github.com/dcferreira/agent-pawl/pull/70))
* When a resume is refused because the workflow file changed, the refusal now names only the steps that actually changed; it listed unchanged steps too. ([#72](https://github.com/dcferreira/agent-pawl/pull/72))
* A crash resume no longer restarts a `human` step's `timeout:`. A crash just before re-entering a looped `wait` step no longer skips that visit or reuses the old deadline. Resuming a blocked `wait` step now counts as a new visit toward `max_visits:`, like every other kind; a wait step blocked and resumed repeatedly can now exhaust. A crash just before an `agentic` step is entered no longer dispatches it flagged as interrupted. A crash just before a `parallel` step is entered no longer routes it to `failure` (blocking the run) instead of dispatching its branches. ([#76](https://github.com/dcferreira/agent-pawl/pull/76))
* A terminal-installed or stale `pawl` earlier on PATH no longer silently drives the plugin's skill - the skill runs the plugin's own launcher, and `pawl run` refuses when its version differs from the plugin whose hooks are active. ([#75](https://github.com/dcferreira/agent-pawl/pull/75))
* `pawl list` with no workflows now says where it looked (on stderr; stdout stays empty). Errors for a missing script or context file now follow the same one-line `<file>: step "<id>": rule 16: <what>; <how to fix>` shape as every other validation error. ([#82](https://github.com/dcferreira/agent-pawl/pull/82))
* `pawl validate`, and `pawl run` when it starts a new run, now enforce format-spec §H rule 16, which was specified but never checked. Every literal script path in a `run:`, `poll:`, postcondition `command:`, invariant `check:` or `!cmd` `context:` must exist and be executable, and a plain `context:` file must exist and be readable. Paths resolve relative to the workflow file, as at runtime. Under `docs/compatibility.md`'s bug clause, a workflow this rejects would have failed at that step, unless an earlier step creates the file during the run. Such a file must be referenced through `${key}` or `!cmd` to pass the check. Resuming a run, `pawl status` and the hooks do not apply the check, so deleting a script after its step has run never strands a live run. ([#69](https://github.com/dcferreira/agent-pawl/pull/69))

## v0.8.0 - 2026-10-15

### Breaking

Upgrading from 0.7: run `pawl validate` (0.8.0) on every workflow first; the stricter validator (rules 30–39) is the likeliest break. Runs started on 0.7 resume on 0.8; runs started on 0.8 cannot be resumed by 0.7. The marketplace plugin bundles its binary, so they update together; if you run the plugin from a checkout or `--plugin-dir` with a standalone `pawl`, update both, or `pawl run` refuses with exit 4. This is the last breaking release before 1.0; see docs/compatibility.md.

* Run directories now carry a format version (format 2) and `plan.json` uses snake_case keys; a run started by this pawl cannot be resumed by an older pawl (downgrading is not supported), while runs started by older pawl still resume. The workflow-changed check now re-digests the pinned plan with the running code, so a future digest change can't falsely refuse an in-flight run. ([#56](https://github.com/dcferreira/agent-pawl/pull/56))
* pawl validate is stricter, so a workflow it previously accepted may now fail (new format-spec §H rules 30–39): each step kind accepts only its own fields (one per-kind table; e.g. question:/poll: on deterministic, attempts: on wait/human/parallel, postcondition: on human/parallel are errors; attempt_key: is allowed on every kind); soft: requires postcondition:; state/args type: is required and must be string|integer|number|boolean|json; default: must match type:; catch[] entries accept only on:/next:, on: must be a failure-type outcome the kind can produce (failure, exhausted, plus timeout on wait/human and partial on foreach), and duplicate or outcomes:-shadowed catch entries are errors; wait/human durations must parse and be > 0; step ids done/blocked and ids equal to a terminal: key are reserved; state/args keys may not be a pseudo-key name (case-insensitive), start with "_" (PAWL__* is reserved for pawl's own env vars), or export as PAWL_ENFORCEMENT/PAWL_STATE_DIR; keys equal ignoring case, or declared in both args: and state:, are errors. ([#58](https://github.com/dcferreira/agent-pawl/pull/58))
* String state now keeps real newlines and tabs instead of storing them as a literal `\u000a`/`\u0009`; every other control character and DEL is still stored as a visible `\u00XX` escape, now uniformly for emit json/pairs and agentic submit (string and json). `max_length` counts the value as stored (a newline is 1). Values stored by an older pawl stay literal on resume (no migration). ([#63](https://github.com/dcferreira/agent-pawl/pull/63))
* A stdout TOKEN may name an author-declared outcome, `failure` (always, no `catch:` needed) or `success` (only if declared under `outcomes:`); the engine-owned `exhausted`, `timeout`, `partial` and `chosen` are never routable from stdout, even when declared, and are now unintelligible stdout (a hard failure). `catch:` no longer makes a token routable. ([#63](https://github.com/dcferreira/agent-pawl/pull/63))
* Agentic `pawl submit` coercion is strict: an `integer` key rejects non-integral or out-of-range numbers (the step retries with the reason in `last_error`) instead of truncating, a number written to a `string` key keeps its own text instead of e.g. `1e+06`, and trailing data after the JSON object is rejected; a pairs-sourced `json` value must be exactly one JSON value. ([#63](https://github.com/dcferreira/agent-pawl/pull/63))
* A command that hits the wall-clock timeout now gets SIGTERM to its process group and up to 5 seconds to exit before SIGKILL (worst case: timeout + 5s), instead of an immediate SIGKILL. ([#63](https://github.com/dcferreira/agent-pawl/pull/63))
* The CLI contract is now frozen and uniform. Every command parses flags the same way: `--flag value` and `--flag=value` both work, an empty value is an error (except `pawl abandon --reason`), a repeated flag is now an error (exit 2) instead of last-wins, and `-h`/`--help` prints that command's usage and exits 0 (also `pawl help`, `pawl --help`, `pawl -h`). Exit codes are one table: 0 ok, 1 not found/ambiguous, 2 your input is wrong (usage or an invalid workflow), 3 run blocked, 4 refused, 5 internal or environment error; a Go panic now exits 5 instead of 2, and `pawl hook` stays fail-open and never exits 2. `pawl validate` now prints validator errors to stderr. `pawl status --json` gains `schema_version: 1`; its `workflow` is now the name `pawl run` accepts (or "" when the file no longer resolves to one) and the absolute path moved to the new `workflow_path`; with several live runs and no `--run`, `--json` lists them all with exit 0. `pawl list` prints TSV (`name`, `repo-local|user`, absolute path), omitting user workflows shadowed by a repo-local one. `pawl run` now refuses with exit 4, naming both versions, when the binary does not match the Claude Code plugin that launched it (the plugin launcher exports `PAWL__PLUGIN_VERSION`; skipped when unset and for `dev` builds). `pawl update` orders pre-release versions by semver precedence (rc.2 before rc.10). ([#62](https://github.com/dcferreira/agent-pawl/pull/62))
* `all_set:` now treats a numeric 0 as unset on every path, as format-spec §D always said; previously a 0 written by an agentic step passed. To check "was written, even if 0", use `equals:` or a `command:` postcondition. ([#64](https://github.com/dcferreira/agent-pawl/pull/64))

### Added

* The release pipeline now supports release candidates (vX.Y.Z-rc.N), published as GitHub prereleases that install.sh, `pawl update` and the repo marketplace never pick up. ([#55](https://github.com/dcferreira/agent-pawl/pull/55))
* `docs/compatibility.md` defines what 1.x keeps stable (the workflow format, the step-script contract, the CLI as scripts use it, the hook entry points, resume across 1.x and the frozen defaults) and what stays internal. format-spec §D now defines `all_set:` precisely, and docs/install.md shows a fail-open wrapper for wiring the hooks without the plugin. ([#65](https://github.com/dcferreira/agent-pawl/pull/65))

### Changed

* A run pawl can't replay (written by a newer pawl, or with a corrupt journal) no longer silently disappears: `pawl run`/`submit`/`poll` refuse it with an upgrade-or-abandon message (exit 4, or 5 for a corrupt journal), `pawl status` shows it, `pawl abandon` ends it, and the hooks keep denying subagent VCS writes while it is live. ([#59](https://github.com/dcferreira/agent-pawl/pull/59))
* A `!cmd` context entry that exits non-zero or times out now adds an engine-written `(context command exited N)` / `(context command timed out)` line under that context item in the DISPATCH block instead of passing silently. ([#63](https://github.com/dcferreira/agent-pawl/pull/63))

### Fixed

* Resuming a run after a crash no longer restarts a `wait` step's `timeout:`; resuming a blocked run still starts a fresh one. ([#56](https://github.com/dcferreira/agent-pawl/pull/56))
* `integer` and `number` state no longer render in exponent form after a resume or between steps (`${n}`, `$PAWL_N` and prose showed `1e+06` for 1000000); integers render as plain decimals and numbers as the shortest exact decimal. ([#63](https://github.com/dcferreira/agent-pawl/pull/63))
* Journal replay now keeps numbers exact: integers above 2^53 survive a resume, and `equals:` compares numeric values by value (1000000 matches 1e6) whether the step ran fresh or after a replay. ([#64](https://github.com/dcferreira/agent-pawl/pull/64))

### Security

* DISPATCH/ASK/TERMINAL/WAIT output now neutralises every control character except newline and tab (ESC/ANSI sequences, VT, FF, 0x1C–0x1E, DEL), U+0085 and the bidi controls into visible escapes, so context bodies or state values can no longer spoof an instruction line in renderers that honour them. ([#63](https://github.com/dcferreira/agent-pawl/pull/63))

## v0.7.0 - 2026-10-14

### Changed

* A `blocked` TERMINAL block now prints its two ways out: a `resume:` field with the exact `pawl run <name> --run <id>` command, checked by resolving the name back to the run's own workflow file (or a `resume_note:` when no name resolves from the current directory), and an `abandon:` field with `pawl abandon --run <id> --reason '<reason>'`. The `/agent-pawl:pawl` skill now treats a blocked run as paused, not finished: it gives the user both commands and never leaves the run silently live. The `ok` block is unchanged. ([#51](https://github.com/dcferreira/agent-pawl/pull/51))

### Fixed

* `pawl abandon --run <id>` now finds a live run in another working copy when the current one has no run with that id, so a stale blocked run whose checkout was deleted can be abandoned from anywhere. Several matches are refused, and so is a non-blocked run that another session is still actively driving.
* The `Stop` hook no longer blocks the driving session's turn when a background subagent has just finished but its result has not been delivered yet (the reviewer race at a `parallel`/`agentic` step). Claude Code drops a finished subagent from `background_tasks` before its result reaches the session. A new `SubagentStop` hook (`pawl hook subagent-stop`, wired in the plugin's `hooks/hooks.json`) records the finish, and the next `Stop` that would block is allowed once, within 60 seconds. Non-plugin users must also wire `SubagentStop` to `pawl hook subagent-stop` in their `settings.json` (see `docs/install.md#hooks`), or the race remains.

## v0.5.0 - 2026-10-06

### Breaking

* `pawl validate` now rejects a negative `max_length:`, a `max_length:` on a key that is not `type: string`, and a `state:` `default:` longer than its `max_length:` (rule 29). A typed `writes:` entry now accepts only `type:` and `max_length:`, and any other field, previously ignored, is a load error.

### Added

* `kind: parallel` now runs `foreach:` fan-out over a runtime-discovered json list with deterministic bodies, per-item postconditions and a `success`/`partial`/`failure` join (see `docs/examples/foreach-fanout`).
* `foreach:` now runs `agentic` bodies: each item is dispatched in one `DISPATCH_PARALLEL` and answered with the new `pawl submit --item N`, and a body's `attempts:` is a per-item budget that re-dispatches only the failed item (see `docs/examples/foreach-agentic`).

### Fixed

* The ASK `submit with:` hint now shows `selected` and `other` as alternatives for single-select human steps, so a session no longer submits both and blocks the run (#23)
* The docs/examples/manage-mr example now passes `pawl validate`: it declares the `pipeline_failed` state key and measures the title length without shell syntax that collides with `${key}`.
* `pawl validate` now suggests `--path <file>` when given a file path instead of a workflow name (#26)
* A step resumed after a crash no longer counts an extra visit: `${visits}` and `max_visits:`/`max_steps:` treat the interrupted step as the same visit, so a `max_visits: 1` step can be resumed instead of exhausting.
* A failed postcondition in a `branches:` parallel branch no longer leaks into the run-wide `${last_error}`; a failed group now sets `${last_error}` to a summary naming each failed branch.
* `max_length:` is now enforced: a `string` write longer than the cap (counted in Unicode code points) is rejected exactly like a type mismatch, so an agentic step retries with the reason in `last_error`. The cap applies on `state:` entries and on typed `writes:` entries, whose `max_length:` was previously dropped silently.

## v0.3.0 - 2026-09-25

### Breaking

* **`pawl run` now refuses to start without the enforcement hooks** (exit 4). It needs a
  `PreToolUse` heartbeat for the working copy from the last 5 minutes. The Claude Code plugin
  wires the hooks for you; for a non-plugin install, see the `settings.json` snippet in
  `docs/install.md`. To opt out, pass `--no-enforcement` or set `PAWL_ENFORCEMENT=off`. Resuming a
  run keeps the mode it started with (#14).

### Added

* **Enforcement hooks** (`pawl hook pre|stop`, #14):
  * `Stop` won't let the driving session end its turn while a run is waiting on a `pawl submit`
    for an `agentic`/`parallel` step.
  * `PreToolUse` enforces `guards:` and stops subagents from mutating git/jj while a run is live.
* **`guards:`** is validated and no longer rejected (#12). Guards are enforced by the
  `PreToolUse` hook. They are advisory regex matches, not a semantic guarantee.
* **`retry:`** on `deterministic` and `wait` steps (#13) re-runs a hard-failed body before any
  outcome is resolved. That covers a non-zero exit, a timeout, or stdout pawl can't parse. It is
  separate from `attempts:`. See format-spec §B.16.
* **`invariants:`** are checked by the engine after every step and every `pawl
  submit`/`pawl poll` (#16). A violation blocks the run with the invariant's `message:`. For a
  `parallel` step, they are checked once, when the group joins.
* **`pawl update [--check] [--version vX.Y.Z] [--force]`** updates the binary in place from a
  GitHub release (#10). It verifies the checksum before writing anything, and it refuses to
  replace a source (`dev`) build unless you pass `--force`.
* The **`review-pr` workflow now converges** (#15). It uses only Claude reviewers, re-reviews only
  the delta after round 1, keeps a findings ledger, uses a scoped fixer, and stops after 4 rounds.
* Docs fixes (#11, #17). The plugin manifest version now tracks the release (0.3.0).

### Known limitations

* The enforcement hooks key on the Claude Code session's start directory. A session that drives a
  run in a different working copy, such as `cd <jj-workspace or git worktree> && pawl run …`,
  never passes the heartbeat gate, and the hooks don't see that run. Start the session in the
  working copy you run in, or pass `--no-enforcement`. Tracked in #18.

## v0.2.0 - 2026-09-23

### Breaking

* **Exit codes now follow the documented table** (`docs/cli.md`):
  * `pawl run`/`submit`/`poll` exit **3** when the run ends BLOCKED. Before, they exited 0.
  * Refusals exit **4**: lock held, workflow file changed, a step or kind that isn't current, or a
    run that has already finished.
  * Engine errors, such as a broken run directory, exit **5**.
  * Validation and YAML parse failures exit **2**. Before, they exited 1.
  * `pawl status` still exits 0 whenever the lookup works. `pawl poll` still exits 0 when the run
    has moved on.
* **`pawl validate --strict` is now an error** (exit 2). It never existed, and before it was read
  as a workflow name. `validate` takes `<workflow-name>` or the new `--path <file>`.
* **New validator rule 18** rejects `context:` entries that start with `!` but lack the YAML
  `!cmd` tag, such as `"!git diff"` or an unquoted `!git diff`. Those entries used to be read as
  file paths. Write `!cmd "git diff"` instead.

### Added

* `pawl abandon --reason <text>`, `pawl status --json`, and `pawl validate --path <file>`.
* The `review-pr` workflow.

### Changed

* `examples/` moved to `docs/examples/`.

## v0.1.0 - 2026-09-22

Initial release. `agent-pawl` (binary `pawl`) is a state-machine workflow engine for Claude Code:
a workflow is one YAML file, sequencing lives only in `next:`/`outcomes:`/`catch:`, and the engine
owns the run cursor and evaluates every postcondition itself.

### Added

* The core engine: `${key}` substitution (`internal/render`), YAML types/loader/validator
  (`internal/spec`), the stdout grammar `deterministic`/`wait` steps use to report outcomes
  (`internal/emit`), the run journal (run directory, event log, pure replay, lock)
  (`internal/journal`), and the run cursor (`internal/engine`).
* The `pawl` CLI and the `/wf` handshake output.
* Three step kinds: `deterministic`, `agentic`, and `parallel`; `wait` and `human` followed shortly
  after.
* `docs/examples/green-tests`, the first verified-runnable example, covered end-to-end by `e2e/`.
* Installation as a Claude Code plugin, alongside `go install`.
* `install.sh` and goreleaser-based release binaries, published via tagged GitHub Releases.
* CI: gofmt, vet, the test suite (including the race detector and staticcheck), `go mod tidy`
  drift checks, and jj-workspace coverage alongside the assumed git path.
* An MIT licence and `AGENTS.md` orientation for AI agents working in the repo.

### Fixed

* Run-directory slug collisions and script paths, closing a path-handling bug found while
  building the run journal.
* Working-copy root resolution no longer shells out to a VCS binary at runtime.

### Changed

* The project was renamed from `wf` to `agent-pawl`, and the binary from `wf` to `pawl`.
