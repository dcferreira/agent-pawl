## v1.1.0 - 2026-11-14

### Added

* `pawl run <name> --from <step>` moves a live run (blocked, or parked at any step) to its current step or to a step it has already entered, and continues from there. State is kept and no counter is reset. A run moved this way resumes on any later 1.x, and on 1.0.0 itself.
* `pawl status` now flags a live run that has had no journal event for 7 days or more: a single run gets an `idle:` line that names `pawl abandon --run <id>`, and each such id in the "multiple runs are live" list gets an `(idle 22d)` suffix. `pawl status --json` gains one key per run, `last_event_time` (RFC3339 UTC, `""` when unknown), so scripts can apply their own threshold.
* Set `PAWL_HOOK_LOG` to an absolute directory to capture what Claude Code sends the hooks: `pawl hook pre|stop|subagent-stop` then append one JSON line per call (payload fields, the live runs and markers pawl saw, the decision and its reason) to `<dir>/<session>.jsonl`. It is off by default, never records a command, `tool_input`, `last_assistant_message`, `transcript_path` or a prompt, and cannot change a hook decision. A diagnostic: the variable and the line shape may change in any 1.x. See docs/troubleshooting.md.

### Fixed

* A blocked run no longer denies its session's subagents' VCS commands (its guards still apply), and the deny for a running run now names the run's state and `pawl abandon --run <id>`. ([#103](https://github.com/dcferreira/agent-pawl/pull/103))
* The hooks no longer treat a redirect as an argument (`git tag --contains HEAD 2>/dev/null` is a listing, not a tag creation), and a pawl called through a shell variable named for it (`"$PAWL" run …`) now writes the heartbeat `pawl run` needs. ([#105](https://github.com/dcferreira/agent-pawl/pull/105))
