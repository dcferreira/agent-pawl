## v0.9.0 - 2026-10-15

### Added

* `docs/examples/README.md` lists which examples are proven in e2e and which are authoring exercises, and a test keeps that true. `wait-for-build`, `human-approval` and `parallel-fanout` now run end to end in `e2e/` (agentic answers canned); `brain-dispatch`, `manage-mr` and `dependency-upgrade` are labelled "Authoring exercise, not run"; `manage-mr` and `dependency-upgrade` ship placeholder scripts for everything they reference, and `brain-dispatch`'s `NOTES.md` lists its unshipped external dependencies. `human-approval/notes.md` is now `NOTES.md`. ([#67](https://github.com/dcferreira/agent-pawl/pull/67))
* `pawl --version` and `pawl -v` print the version, the same as `pawl version`. ([#82](https://github.com/dcferreira/agent-pawl/pull/82))

### Changed

* `pawl run`'s version-mismatch refusal now names the stale binary's path and the exact command to fix it, and the /pawl skill stops and reports it instead of trying to fix the install itself. ([#73](https://github.com/dcferreira/agent-pawl/pull/73))
* The `/pawl` skill now says to pass `subagent_args` to the subagent and to state a field the harness can't enforce (such as `tools`) in the subagent's prompt; the docs explain `blocked` as how a workflow gives up, what `${visits}` means in a terminal message, and how to test failure paths. ([#83](https://github.com/dcferreira/agent-pawl/pull/83))

### Fixed

Fixes that can change how an existing workflow behaves: `pawl validate` and a new `pawl run` now enforce format-spec rule 16 (referenced scripts must exist and be executable; context files must exist) (#69); resuming a blocked `wait` step now counts as a visit toward `max_visits:` (#76); a `human` step's deadline now survives a crash resume (#76); a stale terminal `pawl` is now refused when the plugin's hooks are active (#75).

* The docs' sample output is now captured from real runs (and a test keeps it current); earlier examples showed output pawl never printed. ([#70](https://github.com/dcferreira/agent-pawl/pull/70))
* When a resume is refused because the workflow file changed, the refusal now names only the steps that actually changed; it listed unchanged steps too. ([#72](https://github.com/dcferreira/agent-pawl/pull/72))
* A crash resume no longer restarts a `human` step's `timeout:`. A crash just before re-entering a looped `wait` step no longer skips that visit or reuses the old deadline. Resuming a blocked `wait` step now counts as a new visit toward `max_visits:`, like every other kind; a wait step blocked and resumed repeatedly can now exhaust. A crash just before an `agentic` step is entered no longer dispatches it flagged as interrupted. A crash just before a `parallel` step is entered no longer routes it to `failure` (blocking the run) instead of dispatching its branches. ([#76](https://github.com/dcferreira/agent-pawl/pull/76))
* A terminal-installed or stale `pawl` earlier on PATH no longer silently drives the plugin's skill - the skill runs the plugin's own launcher, and `pawl run` refuses when its version differs from the plugin whose hooks are active. ([#75](https://github.com/dcferreira/agent-pawl/pull/75))
* `pawl list` with no workflows now says where it looked (on stderr; stdout stays empty). Errors for a missing script or context file now follow the same one-line `<file>: step "<id>": rule 16: <what>; <how to fix>` shape as every other validation error. ([#82](https://github.com/dcferreira/agent-pawl/pull/82))
* `pawl validate`, and `pawl run` when it starts a new run, now enforce format-spec §H rule 16, which was specified but never checked. Every literal script path in a `run:`, `poll:`, postcondition `command:`, invariant `check:` or `!cmd` `context:` must exist and be executable, and a plain `context:` file must exist and be readable. Paths resolve relative to the workflow file, as at runtime. Under `docs/compatibility.md`'s bug clause, a workflow this rejects would have failed at that step, unless an earlier step creates the file during the run. Such a file must be referenced through `${key}` or `!cmd` to pass the check. Resuming a run, `pawl status` and the hooks do not apply the check, so deleting a script after its step has run never strands a live run. ([#69](https://github.com/dcferreira/agent-pawl/pull/69))
